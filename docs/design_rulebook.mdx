
# BudgetMeter iOS: Design Rulebook

**Version:** 1.0  
**Purpose:** This document defines the visual identity, layout principles, and interaction patterns for the BudgetMeter iOS app. It ensures a consistent, minimalist, and HIG-compliant user experience.

---

## 1. Core Principles

- **Clarity:** The UI must be clean, legible, and immediately understandable. Avoid visual clutter.
- **Native Feel:** The app should look and feel like it was made by Apple. Use standard components, symbols, and patterns wherever possible.
- **Consistency:** All design elements (colors, fonts, spacing) must be applied consistently across the entire application.

---

## 2. Color Palette

The color palette combines custom brand colors with Apple's system colors to ensure both brand consistency and perfect adaptability for Light Mode, Dark Mode, and accessibility settings.

### Brand Colors
| Role              | Hex Code    | UIKit Implementation       | SwiftUI Implementation     | Usage                                    |
|-------------------|-------------|----------------------------|----------------------------|------------------------------------------|
| **Primary Brand** | `#4A90E2`   | `UIColor(hex: "4A90E2")`   | `Color(hex: "4A90E2")`     | CTAs, primary buttons, highlights        |
| **Secondary**     | `#6B7280`   | `UIColor(hex: "6B7280")`   | `Color(hex: "6B7280")`     | Secondary text, borders, inactive elements |
| **Background**    | `#FAFAFA`   | `UIColor(hex: "FAFAFA")`   | `Color(hex: "FAFAFA")`     | Cards, surfaces, input backgrounds       |
| **Success**       | `#10B981`   | `UIColor(hex: "10B981")`   | `Color(hex: "10B981")`     | Positive indicators, success messages    |

### System Colors (Semantic)
| Role              | Color Name          | UIKit Equivalent          | SwiftUI Equivalent      | Usage                                        |
|-------------------|---------------------|---------------------------|-------------------------|----------------------------------------------|
| **Income**        | System Green        | `.systemGreen`            | `Color.green`           | Income values, positive financial indicators  |
| **Expense**       | System Red          | `.systemRed`              | `Color.red`             | Expense values, negative indicators, delete   |
| **Warning**       | System Orange       | `.systemOrange`           | `Color.orange`          | Warnings, neutral alerts                     |

### Color Implementation Notes
- **Dark Mode Adaptation:** Brand colors should be tested and adjusted for Dark Mode compatibility
- **Accessibility:** All color combinations must meet WCAG AA contrast requirements (4.5:1 ratio)
- **Color Extensions:** Create SwiftUI Color extensions for brand colors to enable `Color.brandPrimary` syntax

---

## 3. Typography

- **Font:** **SF Pro**. The app must use the standard system font. Do not bundle custom fonts.
- **Weights:** Use **Regular** for body text and **Bold** or **Semibold** for titles and emphasis.
- **Sizes:**
    - **Body/Input:** 17pt (Standard)
    - **Titles (Large):** 22pt (Bold)
    - **Subheadings:** 16pt (Semibold)
- **Rule:** All text must support **Dynamic Type**. Use built-in text styles like `.body`, `.headline`, `.subheadline` where possible.

---

## 4. Layout & Spacing

- **Minimum Padding:** **16pt** for screen edges and around major content blocks.
- **Standard Spacing:** **8pt** for spacing between related elements (e.g., items in a VStack, cards in a list).
- **Corner Radius:** **12pt** for all cards and large buttons to maintain a soft, modern aesthetic.
- **Touch Targets:** All interactive elements (buttons, list rows, inputs) must have a minimum touch target size of **44x44pt**.

---

## 5. Iconography

- **Source:** **SF Symbols only.** Do not use custom PNG, SVG, or other image assets for icons.
- **Implementation:** Icons should be treated like text—they should scale with Dynamic Type and adopt the surrounding text color unless a specific semantic color (e.g., `Color.red`) is required.
- **Key Symbols for BudgetMeter:**
  - **Empty States:** `tray`, `creditcard`, `chart.line.uptrend.xyaxis`
  - **Categories:** Use appropriate SF Symbols for expense/income categories
  - **Navigation:** `house`, `dollarsign.circle`, `chart.bar`

---

## 6. Components

- **Buttons:** Use standard SwiftUI button styles (`.borderedProminent`, `.plain`). Ensure they meet the 44pt minimum touch target.
- **Cards:** Use a container with a `.secondarySystemBackground` color and a 12pt corner radius.
- **Form Inputs:** Use standard SwiftUI `TextField`s with the `.decimalPad` keyboard type.

---

## 7. Motion & Haptics

- **Animations:** Keep animations minimal and purposeful. Use the default SwiftUI animations (`.animation(.default, value: ...)`).
- **Haptics:** Use subtle haptics for confirmation of user actions.
    - **Action:** Saving a value, deleting an item.
    - **Feedback:** A single, light tap (`UIImpactFeedbackGenerator(style: .light)`).

---

## 8. App Icon & Splash Screen

- **App Icon:** The design should be minimalist, flat, and modern. It should be recognizable and work well on a variety of wallpapers.
- **Splash Screen (Launch Screen):** The launch screen storyboard must be simple: it should contain only the app icon centered on a solid background color that matches the app's theme. **No text or other graphics.**

---

## 9. Empty States & Illustrations

- **No Custom Illustrations:** Use SF Symbols exclusively for visual elements and empty states.
- **Empty State Components:**
  - **Icon:** Large SF Symbol (e.g., `tray`, `creditcard`, `chart.line.uptrend.xyaxis`)
  - **Message:** Short, encouraging text using secondary text color
  - **Action:** Optional primary button using brand color for next steps
- **Examples:**
  - Empty expenses: `creditcard` icon + "Add your first expense to get started!"
  - Empty income: `dollarsign.circle` icon + "Add your income sources"
  - Empty summary: `chart.line.uptrend.xyaxis` icon + "Enter your finances to see insights"

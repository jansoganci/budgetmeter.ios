# BudgetMeter iOS: Design Rulebook v2.0

**Version:** 2.0
**Design Language:** Modern Financial Dashboard (iOS-Adapted)
**Purpose:** This document defines the visual identity, layout principles, and interaction patterns for the BudgetMeter iOS app with the new dashboard-focused design language. It ensures a consistent, modern, data-driven user experience while maintaining iOS platform conventions.

---

## 1. Core Principles

- **Data-First:** Metrics, charts, and financial insights should be prominent and immediately visible. The interface prioritizes information density without sacrificing clarity.
- **Modern Boldness:** Move away from subtle minimalism toward confident, prominent UI elements with strong visual hierarchy.
- **iOS Native:** Despite the dashboard aesthetic, maintain iOS platform conventions—no hover effects, proper navigation patterns, full dark mode support, and haptic feedback.
- **Performance:** Smooth animations and transitions are non-negotiable. All data visualizations must render at 60fps.

## 3. Typography

**Font Family:** **SF Pro** (System Font) — No custom fonts. Leverage SF Pro's excellent tabular figure support for financial data.

### Type Scale

| Style                    | Size      | Weight      | Usage                                              |
|--------------------------|-----------|-------------|---------------------------------------------------|
| **Hero Metric**          | 48pt      | Bold        | Net flow value, large financial numbers            |
| **Large Metric**         | 34pt      | Bold        | Secondary metrics, savings amounts                 |
| **Medium Metric**        | 24pt      | Semibold    | Card values, interval amounts                      |
| **Small Metric**         | 17pt      | Semibold    | Inline metrics, list values                        |
| **Section Title**        | 20pt      | Semibold    | Card titles, section headers                       |
| **Card Label**           | 15pt      | Medium      | Labels, descriptions within cards                  |
| **Caption**              | 13pt      | Regular     | Timestamps, secondary info, footnotes              |
| **Trend Indicator**      | 14pt      | Medium      | Percentage changes, "+12.5%"                       |

### Typography Rules

1. **Tabular Figures:** All financial values MUST use `.monospacedDigit()` modifier for smooth animations
2. **Dynamic Type:** Support Dynamic Type scaling for accessibility (minimum .large, maximum .accessibility3)
3. **Number Formatting:**
   - Currencies: `$2,450.50` format with locale-aware symbols
   - Percentages: `+12.5%` with explicit sign for trends
   - Large numbers: `562K` or `1.2M` for compact display when space-constrained
4. **Line Spacing:** Use default SF Pro line spacing (do not override)
5. **Letter Spacing:** Default tracking (no custom kerning)

### SwiftUI Text Modifiers

```swift
// Hero metric
Text(value)
    .font(.system(size: 48, weight: .bold, design: .default))
    .monospacedDigit()
    .foregroundColor(.brandPositive)

// Section title
Text("Financial Health Score")
    .font(.system(size: 20, weight: .semibold))
    .foregroundColor(.textPrimary)

// Card label
Text("Net Flow This Month")
    .font(.system(size: 15, weight: .medium))
    .foregroundColor(.textSecondary)
```

## 4. Layout & Spacing

### Spacing System

The new design uses a **larger, more generous spacing system** to create breathing room and visual hierarchy.

| Token           | Value    | Usage                                                  |
|-----------------|----------|--------------------------------------------------------|
| **xs**          | 4pt      | Icon-to-text spacing, tight groupings                  |
| **sm**          | 8pt      | Related elements within a card                         |
| **md**          | 12pt     | Vertical spacing between card content sections         |
| **lg**          | 16pt     | Horizontal screen padding (mobile)                     |
| **xl**          | 24pt     | Card gap spacing, section separation, desktop padding  |
| **2xl**         | 32pt     | Major section breaks                                   |

### Layout Rules

1. **Screen Padding:**
   - **iPhone:** 16pt horizontal padding
   - **iPad:** 24pt horizontal padding
   - **Max Width:** None (full-width, iOS convention) — Unlike web design, iOS apps use full screen width

2. **Card Spacing:**
   - **Between cards:** 24pt vertical gap
   - **Card internal padding:** 20pt all sides

3. **Grid Layouts:**
   - **2-column grid (iPhone):** 12pt gap
   - **3-column grid (iPad):** 16pt gap
   - Use `LazyVGrid` with `GridItem(.flexible())` for responsive grids

4. **Corner Radius:**
   - **Cards:** 16pt (increased from previous 12pt)
   - **Buttons:** 12pt
   - **Small elements (badges, chips):** 8pt
   - **Progress bars:** 8pt

5. **Touch Targets:**
   - **Minimum:** 44x44pt (HIG requirement)
   - **Recommended for primary actions:** 50pt height

- **Interaction:** No direct interaction (tap on parent card)

**Implementation Pattern:**
```swift
HStack(alignment: .bottom, spacing: 2) {
    ForEach(Array(data.enumerated()), id: \.offset) { index, value in
        RoundedRectangle(cornerRadius: 2, style: .continuous)
            .fill(Color.chartInactive)
            .frame(width: 4, height: normalizedHeight(value))
            .animation(
                .spring(response: 0.8, dampingFraction: 0.7)
                .delay(Double(index) * 0.05),
                value: animationTrigger
            )
    }
}
.frame(height: 60)
```

## 7. Motion & Animation

### Animation Principles

1. **Purpose-Driven:** Every animation must serve a functional purpose (feedback, transition, or guidance)
2. **Performance:** All animations must maintain 60fps on iPhone 12 and newer
3. **Consistency:** Use standardized timing curves and durations
4. **Accessibility:** Respect "Reduce Motion" system setting

### Standard Timing System

| Duration    | Use Case                                        | Curve                                    |
|-------------|-------------------------------------------------|------------------------------------------|
| **0.3s**    | Quick feedback, button taps, toggles            | `.easeInOut`                             |
| **0.6s**    | Card appears/dismisses, navigation              | `.easeOut`                               |
| **0.8s**    | Bar chart animations                            | `.spring(response: 0.8, damping: 0.7)`   |
| **1.2s**    | Progress bar fills, value counts                | `.spring(response: 1.2, damping: 0.7)`   |
| **1.5s**    | Circular progress animations, health score      | `.spring(response: 1.5, damping: 0.7)`   |

### Spring Animation Standards

```swift
// Quick spring (buttons, toggles)
.spring(response: 0.3, dampingFraction: 0.7)

// Medium spring (cards, reveals)
.spring(response: 0.6, dampingFraction: 0.75)

// Slow spring (hero elements, progress)
.spring(response: 1.2, dampingFraction: 0.7)
```

### Staggered Animations

For lists of elements (insight cards, bar charts):
```swift
.animation(
    .spring(response: 0.6, dampingFraction: 0.7)
    .delay(Double(index) * 0.05),
    value: animationTrigger
)
```

### Number Counting Animation

For financial values that animate from 0 to target:
```swift
struct AnimatedNumberView: View {
    let target: Double
    @State private var current: Double = 0

    var body: some View {
        Text(formatCurrency(current))
            .onAppear {
                withAnimation(.spring(response: 1.2, dampingFraction: 0.8)) {
                    current = target
                }
            }
    }
}
```

### Reduce Motion Support

Always provide non-animated fallbacks:
```swift
@Environment(\.accessibilityReduceMotion) var reduceMotion

withAnimation(reduceMotion ? .none : .spring(response: 0.6)) {
    // animation code
}
```

## 8. Interaction Patterns (iOS Adaptations)

### 8.1 Card Interactions

**Web Pattern (Hover):** Cards scale 1.02x and increase shadow on hover
**iOS Adaptation:** Cards use press state with haptic feedback

**Implementation:**
```swift
@State private var isPressed = false

CardContent()
    .scaleEffect(isPressed ? 0.98 : 1.0)
    .animation(.spring(response: 0.3, dampingFraction: 0.6), value: isPressed)
    .onLongPressGesture(minimumDuration: .infinity, maximumDistance: .infinity, pressing: { pressing in
        isPressed = pressing
        if pressing {
            UIImpactFeedbackGenerator(style: .light).impactOccurred()
        }
    }, perform: {})
    .onTapGesture {
        navigateToDetail()
    }
```

**Rules:**
- Scale down to **0.98x** on press (not up like hover)
- Trigger **light haptic** on press start
- Use **medium haptic** for confirmation actions
- No continuous hover states (iOS limitation)

### 8.2 Navigation Patterns

**Primary Navigation:** Tab bar at bottom (iOS standard)
- **Home:** Dashboard view (new design)
- **Income:** Income entry and history
- **Expenses:** Expense entry and history
- **Insights:** Detailed charts and analysis
- **Settings:** App preferences

**Secondary Navigation:** NavigationStack for drill-downs
- Card tap → Detail view with back button
- Use `.navigationTitle()` and `.navigationBarTitleDisplayMode(.large)`
- Swipe from left edge to go back (standard iOS gesture)

**Modal Presentations:** Sheet for input forms
```swift
.sheet(isPresented: $showingAddIncome) {
    AddIncomeView()
        .presentationDetents([.medium, .large])
        .presentationDragIndicator(.visible)
}
```

### 8.3 Pull-to-Refresh

Implement pull-to-refresh for data updates:
```swift
ScrollView {
    // content
}
.refreshable {
    await refreshData()
}
```

### 8.4 Context Menus

Long-press on cards shows context menu:
```swift
.contextMenu {
    Button(action: edit) {
        Label("Edit", systemImage: "pencil")
    }
    Button(action: share) {
        Label("Share", systemImage: "square.and.arrow.up")
    }
}
```

## 10. Dark Mode Specifications

Full dark mode support is **mandatory**. All colors must have dark mode variants.

### Design Adjustments for Dark Mode

1. **Reduce Contrast:** Slightly reduce opacity of pure whites (90% opacity)
2. **Shadow Adjustments:** Use lighter shadows with more spread
3. **True Black:** Use `#000000` for background (OLED optimization)
4. **Elevated Surfaces:** Cards should be `#1F2937` (not pure black)
5. **Gradient Adjustments:** Reduce gradient intensity by 20%

### Testing Requirements

- Test every screen in both light and dark mode
- Verify contrast ratios meet WCAG AA (4.5:1)
- Check color blindness modes (protanopia, deuteranopia, tritanopia)
- Use Xcode Accessibility Inspector

## 11. Accessibility Requirements

### Mandatory Compliance

1. **VoiceOver Support:**
   - All interactive elements have `.accessibilityLabel()`
   - Charts provide textual descriptions: "Your spending increased by 15% this month"
   - Progress indicators announce percentage: "Health score: 78 out of 100"

2. **Dynamic Type:**
   - Support up to `.accessibility3` size
   - Test all layouts at largest text size
   - Allow text to wrap, not truncate

3. **Color Independence:**
   - Never rely solely on color to convey information
   - Use icons + text for trends (not just red/green)
   - Provide alternative indicators (arrows, labels)

4. **Touch Targets:**
   - Minimum 44x44pt for all tappable elements
   - Increase padding if needed to meet requirement

5. **Reduce Motion:**
   - Provide instant transitions when enabled
   - Disable animated number counting (show final value immediately)

## 13. Performance Guidelines

### Optimization Requirements

1. **60fps Mandate:** All animations and scrolling must maintain 60fps
2. **Lazy Loading:** Use `LazyVStack` and `LazyHStack` for lists
3. **Image Optimization:** No images in this design (SF Symbols only)
4. **Chart Rendering:**
   - Limit bar chart data points to 50 per view
   - Use `GeometryReader` sparingly (performance impact)
5. **State Management:**
   - Minimize `@State` re-renders
   - Use `@StateObject` for ViewModels
   - Debounce rapid updates (e.g., live meter)

### Memory Guidelines

- Avoid creating large arrays in view body
- Cache formatted strings (currency, dates)
- Release resources in `onDisappear`

## Appendix B: Example Code Snippets

### Adaptive Color Extension

```swift
extension Color {
    init(light: Color, dark: Color) {
        self.init(UIColor { traitCollection in
            switch traitCollection.userInterfaceStyle {
            case .dark:
                return UIColor(dark)
            default:
                return UIColor(light)
            }
        })
    }
}
```

### Standard Card Modifier

```swift
extension View {
    func dashboardCard() -> some View {
        self
            .padding(20)
            .background(Color.cardBackground)
            .cornerRadius(16)
            .shadow(color: .black.opacity(0.08), radius: 8, x: 0, y: 2)
    }
}
```

### Animated Number Text

```swift
struct AnimatedMetric: View {
    let value: Double
    @State private var displayValue: Double = 0

    var body: some View {
        Text(formatCurrency(displayValue))
            .font(.system(size: 48, weight: .bold))
            .monospacedDigit()
            .onAppear {
                withAnimation(.spring(response: 1.2, dampingFraction: 0.8)) {
                    displayValue = value
                }
            }
    }
}
```
